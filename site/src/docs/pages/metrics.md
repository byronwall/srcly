# Understand metrics

Srcly measures source structure and selected language signals. Metrics appear in the treemap, explorer, Hot Spots, reports, and code viewer. Each metric has a defined scope and aggregation rule; interpret it with its label and availability.

## Common measurements

- **LOC** counts nonblank, noncomment lines of code. Folder and file totals aggregate child values.
- **Complexity** is cyclomatic complexity (CCN). A function has its own value. A file or folder shows the maximum among its functions and names the function that sets it. The average complexity is a separate metric.
- **Cognitive complexity** estimates branching and nesting using Sonar's rules. It is available for TypeScript, JavaScript, and Python.
- **Nesting depth, function length, and parameter count** describe code shape. Their aggregation can differ; the metric catalog and UI identify the measure.
- **Component metrics** describe detected React or Solid components, including component LOC, hooks, effects, JSX depth, props, inline handlers, and conditionals.
- **TypeScript signals** include explicit `any` and TypeScript suppression directives.
- **Comment noise** flags selected patterns such as long comment blocks or commented-out code. It is a heuristic, not a style verdict.
- **Git activity** includes commit count and churn over a selected history window. It depends on available Git history.

Other measurements include file size, imports, exports, TODOs, Markdown data URLs, and language-specific metrics. Detail metrics provide context; they are not all risk scores.

## Why a metric can be N/A

N/A means a metric does not apply to that node, its analyzer did not measure it, or required data was unavailable. For example, component metrics do not apply to a file with no detected component. Some checks depend on project configuration or tools. Git activity can be unavailable when Git history is missing.

Srcly preserves N/A as a distinct state. It is never zero. In comparisons, a metric available on only one side is a coverage change and has no delta. This prevents a missing measurement from appearing to be an improvement.

## Read aggregated values carefully

Folder values summarize children according to the metric's rule. Some sum; some use the maximum; others use an average. For complexity, a folder's maximum points to a witness function. Do not read that maximum as the total complexity of all code in the folder.

Metrics help compare similar code and direct attention. They do not measure correctness, security, or maintainability as a single objective score. Validate a signal against the source, tests, and the project's own standards.
