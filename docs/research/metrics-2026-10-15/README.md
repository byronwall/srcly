# Better information from Srcly metrics

Start by making existing measurements trustworthy. Then test which signals change useful decisions beyond complexity and size.

The research covers 32 API fields, 27 report definitions, 22 selectable metrics, 21 candidates, and 19 tool comparisons. Original outputs remain unchanged in [originals](originals/). The [full report](originals/research-report.md), [metric inventory](originals/current-metrics.json), and [tool survey](originals/tool-survey.md) contain the detail.

## Recommended order

| Initiative | Result | First proof |
| --- | --- | --- |
| [Metric trust](../../intent/metric-trust/shape-brief.md) | Correct scope, units, support, rollups, and ranking | A measured zero differs from unavailable data in one real scan and report |
| [Portfolio evaluation](../../intent/metric-portfolio/shape-brief.md) | Evidence for a compact default and useful diagnostics | Three pinned repositories reveal retained and rejected decision cases |
| [Git activity](../../intent/git-activity/shape-brief.md) | Explain why difficult code deserves attention now | Verified file histories change a justified priority decision |
| [Imported quality evidence](../../intent/imported-quality-evidence/shape-brief.md) | Inspect cycles, clones, diagnostics, and test gaps | An existing graph edge leads to its original source declaration |

These are planned initiatives, with implementation plans and validated maps. This PR implements none of them. The first investment is metric trust and a small portfolio pilot. The other initiatives define independently gated next steps.

## Portfolio direction

Use correctly scoped function complexity with a source location, size context, and analysis availability as the initial view. Keep nesting and arity available for detail. Comments, TODOs, type counts, import syntax counts, and JSX counters can support inspection without becoming automatic quality penalties.

The strongest additional information appears to come from different inputs: Git activity, dependency relationships, clone peers, typed findings, and test artifacts. Their usefulness remains a hypothesis until the proposed proofs run. High correlation can still leave valuable exceptions. Low correlation can simply mean noise or unsupported analysis.

Compare a compact default against the full, organized catalog. Measure rank overlap and size-adjusted relationships within language and scope groups. Also review whether a metric changes the next action. Do not remove a metric solely because its correlation is high.

## CRAP

CRAP combines method complexity and coverage: `C² × (1 − coverage_fraction)³ + C`. The original article names Alberto Savoia and Bob Evans and specifies basis-path coverage. A line-coverage variant must identify that substitution. Missing coverage stays unknown. The historical threshold was experimental. [Creator article](https://www.artima.com/weblogs/viewpost.jsp?thread=215899).

The formula adds no mathematical information once its inputs are known. It may still help someone notice a useful combination. Compare a component table against an optional CRAP view before adopting it. Never add complexity, coverage, and CRAP as three independent votes.

## What changed during integration

- Consolidated eight research groups into four initiatives with explicit dependency and rejection gates.
- Kept the existing dependency renderer and its geometry rules. Graph evidence work extends that path.
- Rejected default backward-compatibility layers, speculative schema infrastructure, and a twelve-repository study before a useful pilot.
- Deferred persistent triage, trends, mutation runners, general cohesion analysis, and new framework rule engines.
- Kept all current-field and candidate dispositions traceable in [reconciliation](reconciliation.md).

See [independent checks and limits](verification.md) and [collection hashes](collection-manifest.json). No correlations, product usability results, or predictive validity measurements were performed.
