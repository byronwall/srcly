## Existing metric dispositions

Every API field has a disposition in [current-metrics.json](originals/current-metrics.json). Accept its keep/change/demote/investigate classification as a planning proposal, with these qualifications:

- Demote means remove unsupported quality judgments and move useful data into detail. It does not require API compatibility support.
- Change means prove the intended measurement using small cases before altering extraction or aggregation.
- Keep preserves neutral context, not a positive claim about quality.
- Investigate applies to render branching. Keep it out of default ranking until its definition and traversal behavior are proved.
- Do not add every missing rollup mechanically. A precise file-only diagnostic can be sufficient.
- Correct README complexity wording; preserve the existing maximum and separate average fields.

The 12 change, 16 demote, three keep, and one investigate records cover all 32 fields. No field is silently dropped.

## Tool presentation lessons

Adopt source-linked drilldown, separate size/color choices, explicit comparison populations, and a useful list beside the map. Evaluate two-axis comparisons before combined scores. Reuse the current bounded graph focus. Defer dependency matrices until focused graphs fail a concrete task. Do not copy hosted dashboards, universal quality gates, remediation-hour estimates, or developer rankings.

The survey records documentation and four static image inspections. It does not establish live usability or comparative performance. Retain its version and licensing caveats. This plan imports existing artifacts before considering any bundled analyzer or rule assets.
