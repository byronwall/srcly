# A metric portfolio that earns its attention

## My read

Byron wants each metric to reveal something useful that other metrics miss. A large catalog can create the appearance of insight while repeating size or branching in several forms. The intended result is a clear set of review decisions, not the largest number of counters or the lowest pairwise correlations.

This initiative establishes which measurements deserve default attention, optional detail, or no place in Srcly. It compares the proposed compact portfolio with a full organized catalog. Both remain valid candidates until evidence separates them. The study must allow the compact proposal to lose when it hides important cases.

The first audience is Byron reviewing personal repositories locally. A small study can reveal bad definitions, obvious overlap, and useful exceptions without claiming universal statistical validity. Broader language claims need later evidence. The work should make additions cheaper to reject before they become permanent UI and maintenance obligations.

## What matters most

- Separate shared formulas, observed association, and distinct decision value.
- Control for size, language, scope and unavailable analysis.
- Keep useful exceptions even when metrics correlate strongly.
- Reject noisy metrics even when their correlations are low.

## Boundaries

Begin after metric trust provides reliable populations and support. Use three explicitly selected local or public repositories at pinned revisions. Do not search private folders for research subjects or run their test configurations automatically.

Do not train a defect predictor, estimate remediation hours, or promise a statistically representative result. A proposed twelve-repository extension is conditional on the pilot being useful. No metric is removed solely because a coefficient crosses a threshold.

## What seems settled

CCN, nesting, average function size and several counts overlap conceptually. That does not establish measured redundancy. CRAP is exactly derived from complexity and coverage, but its presentation could still improve a decision. These are different questions.

The research supplies definitions, candidate proofs and counterexamples. It does not supply repository correlations or product tests. Current API/report/selector coverage must remain traceable throughout the evaluation.

## Next step after confirmation

Build a small reproducible comparison artifact from corrected measurements. Use deliberate equal-size and equal-CCN examples before the repository pilot. Then ask Byron to judge a small shuffled set of source-backed decisions. The [plan](implementation-plan.md) separates that human observation from data collection. All execution remains planned.
