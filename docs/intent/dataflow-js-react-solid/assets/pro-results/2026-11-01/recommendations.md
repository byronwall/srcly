# Recommendations — stable decisions and implementation destinations

**Decision:** build exact, reviewable static semantics and actual-JavaScript access in all three environments; use bounded runtime assertions to challenge the models; keep observation packets optional until they add a justified finding. Baseline: `e07cc510087b5c028273cad785b97ee36c6c3b35`. Checked: 2026-11-01. No repository implementation was performed.

This ledger contains **22 Build, 2 Explore, 2 Defer, and 2 Avoid decisions**. Stable IDs are the same as [implementation-plan.md](implementation-plan.md). [research-report.md](research-report.md) provides the source ledgers, matrices, primary links, qualifications and historical-versus-executed distinctions. [experiment-plan.md](experiment-plan.md) specifies the discriminating controls. A Build decision is a recommendation for Codex implementation, not a claim that the change is already made or universally proved.

## Priority and uncertainty

Immediate highest-value delivery is **SH-01 + minimal SH-02**, with **JS-01**, **RE-01**, and **SO-01** as the three first environment milestones. Exact graph manifestations of inspected rule defects remain unexecuted hypotheses until their cases run. Conservative may-flow unions are legitimate when labelled honestly; wrong equality/result channels and false exact provider selection are separate issues. No numerical benefit, performance gain, or ecosystem coverage percentage is promised.

Access was sufficient for these recommendations: exact baseline/proposal and packet source were inspected; current primary sources were checked. Remaining version-byte preflights, graph trials and optional packet-review gains are explicit in the experiment plan. All three environments have substantive matrices, five ranked risks, discriminating experiments and full implementation tracks.
